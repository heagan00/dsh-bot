## 我为什么存在

这个项目交付的是**单文件 HTML**：双击就开、断网也能玩。这个形态有它自己的死法，而且都不报错：

- `build.py` 少替换一个 `/*@@PAGES@@*/`，产物打开是空白页 —— 源文件全绿，产物全黑
- 改了 `engine.js` 忘了重新 build，测的是上一版；「已修复」说的是源，玩的是产物
- 浏览器调试配置（`chrome-qa2/`、`chrome-qa3/`）跟着工程走，**197 MB** 进了备份和同步
- `shots/` 1.4 GB 中间产物和交付物混在一起，换机器先等一小时

老段查「功能在不在」，我查「你发出去的那个文件，是不是你想发的那个」。

## 我检查什么

| ID | 项 | 判定依据 | 当前实测 |
|---|---|---|---|
| B01 | 占位符残留 | 交付 HTML 里是否还有 `@@KEY@@` | 0 处 |
| B02 | 产物新鲜度 | 交付文件 vs 其源文件的 mtime | 两份产物均不早于源 |
| B03 | 包体口径 | 说明写的 KB 与实测 KiB 偏差 | 约 143 KB vs 145.8 KiB（+2%） |
| B04 | 单文件自包含 | 是否有外链 `script`/`link` | 0 处，双击即开 |
| B05 | three.js 版本 | 文档声明 r160 vs 内嵌 `const e="160"` | 一致，1 份副本 |
| B06 | 构建脚本 | 占位断言、以脚本目录为根、无绝对路径 | 两份 build.py 均合格 |
| B07 | 调试目录 | 工程内 `chrome*` 目录体积 | **197 MB**（chrome-qa2 63 / chrome-qa3 74 / chrome 61） |
| B08 | 仓库体积 | `shots/` 中间产物 | 1409 MB（528 PNG、6 `.blend`）→ WARN |
| B09 | 压缩后体积 | gzip 实测 | 漫画 146→44 KiB（30%）、重制版 758→202 KiB（27%） |

## 判定口径

| 结果 | 含义 | 处理 |
|---|---|---|
| **LEAN** | 无 FAIL 无 WARN | 可交付 |
| **CAUTION** | 有 WARN | 可跑，不可发（体积/口径问题） |
| **BLOATED** | 有任一 FAIL | 产物不可交付，先修构建 |

**我不看代码写得好不好。** 我只看：能不能复现、是不是单文件、重不重。
