# 刘哥 · 周哥提醒复核

| 项 | 内容 |
|---|---|
| 名字 | 刘哥 |
| 岗位 | 全栈工程师 / 主程（复核） |
| 频率 | **由周哥弹窗触发**（无独立定时） |
| 任务名 | 无独立任务；周哥触发 |
| 输入 | `sync/reports/zhou-ge-latest.json` |
| 审计器 | `tools/liu-ge-audit.mjs` |
| UI | `sync/liu-ge.ps1`（主屏底部中间） |
| 报告 | `sync/reports/liu-ge-latest.md` / `.json` |
| 日志 | `sync/logs/liu-ge.log` |

## 它做什么

1. 先刷新周哥的会话分析。
2. 逐条复核周哥的提醒是否成立。
3. 只有判定为**误报/没必要**时，才在主屏底部中间弹窗。
4. 弹窗指出：
   - 周哥说错了什么
   - 周哥为什么会误判
   - 会话为什么其实没问题
   - 刘哥的建议

## 典型误报

| 周哥的提醒 | 刘哥的反证 |
|---|---|
| token 高就是浪费 | 会话有多次落盘，token 含长上下文/缓存，任务在推进 |
| 重复 read 就是空转 | 审查/排错需要交叉核对，读可缓存、重跑才是浪费 |
| 没 edit 就是没产出 | 用户要的是分析/审查/方案，不落盘是任务性质 |
| 相似目标就是并发重复 | 只有一个会话 active，另一个已结束 |
| 会话结束还报 job/retry | 已无活跃 turn，不会继续消耗 |

## 关闭方式

刘哥弹窗**不会自动关闭**。弹窗底部有两个勾选项：

```text
[ ] 同意（刘哥判断正确，记入周哥记忆）
[ ] 不同意（周哥判断仍成立）
```

关闭时必须先勾选其一，再点右上角 `×`：

```text
确认关闭刘哥提醒？
[保留] [确认关闭]
```

- 选“保留”会继续保留
- 选“确认关闭”才关闭
- 只有点“确认关闭”时，才把选择正式写入 `sync/memory/zhou-memory.json` 和 `周哥的小脑袋瓜.md`
- 周哥会读取该记忆，对同一会话、同一类已确认误报不再重复弹
- 若同一模式再次出现，刘哥会用“【重复误报 · 严厉纠偏】”措辞提醒

## 启动方式\n\n周哥检测到需要弹窗时，会直接启动刘哥复核；不再有“刘哥每 5 分钟”任务。\n\n## 手动\n
```cmd
schtasks /Run /TN "刘哥 · 周哥复核"
powershell.exe -NoProfile -STA -File "sync\liu-ge.ps1" -NoToast
```
